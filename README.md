# n8n Self-Hosted Lab

A Docker-based proof of concept for running self-hosted [n8n](https://n8n.io), with SQLite and PostgreSQL configurations.

Repository: [JeanneBM/n8n-self-hosted-lab](https://github.com/JeanneBM/n8n-self-hosted-lab)

## Requirements

- Docker with Docker Compose v2+
- Enough memory for n8n and your workflows; allow additional capacity for PostgreSQL

## Quick start (SQLite)

Run these commands from the repository root:

```bash
git clone https://github.com/JeanneBM/n8n-self-hosted-lab.git
cd n8n-self-hosted-lab
cp .env.example .env
docker compose up -d
```

Open **http://localhost:5678** and create the owner account on first launch.

## PostgreSQL alternative

Choose one database configuration at a time. Switching configurations does not migrate workflow or credential data automatically.

```bash
cp .env.example .env
# Set a strong POSTGRES_PASSWORD in .env before starting.
docker compose -f compose.postgres.yml up -d
```

For all subsequent PostgreSQL operations, use `docker compose -f compose.postgres.yml` instead of `docker compose`.

│   └── restore.sh           # Restore an n8n volume backup

## Common commands

| Action | Command |
|---|---|
| Start | `docker compose up -d` |
| Stop | `docker compose down` |
| Logs | `docker compose logs -f n8n` |
| Status | `docker compose ps` |
| Pull the configured image and restart | `docker compose pull && docker compose up -d` |
| Back up the n8n volume | `bash scripts/backup.sh` |
| Restore the n8n volume | `bash scripts/restore.sh backups/n8n-backup-TIMESTAMP.tar.gz` |

The n8n image is pinned in both Compose files. Change the image tag deliberately when upgrading.

The backup and restore scripts use the default SQLite Compose configuration. They back up only the n8n volume; a PostgreSQL deployment also requires a separate database backup and a coordinated restore procedure.

## Configuration

Copy `.env.example` to `.env` and adjust the settings.

| Variable | Purpose | Default |
|---|---|---|
| `GENERIC_TIMEZONE` | Schedule Trigger time zone | `Europe/Warsaw` |
| `TZ` | Container time zone | `Europe/Warsaw` |
| `N8N_HOST` | Instance hostname | `localhost` |
| `N8N_PORT` | Configured n8n port | `5678` |
| `N8N_WEBHOOK_URL` | Webhook URL setting passed by this lab | Unset |
| `N8N_EDITOR_BASE_URL` | Editor base URL | Unset |
| `N8N_ENCRYPTION_KEY` | Optional explicit credential encryption key | Generated by n8n |
| `POSTGRES_PASSWORD` | PostgreSQL password | Replace the example value |

To supply an explicit encryption key, set it in `.env` and uncomment its environment entry in the selected Compose file.

The `n8n-self-hosted-lab_data` volume contains n8n settings and, in the SQLite variant, the database. Preserve the credential encryption key when restoring or moving an instance.

### Existing installations after the repository rename

Docker resources now use the `n8n-self-hosted-lab` prefix. Renaming the repository does not rename or migrate existing Docker volumes. Back up the previous instance before starting the renamed configuration. To back up an existing volume, pass its actual name with `VOLUME_NAME=<existing-volume-name> bash scripts/backup.sh`. Restore into the new volume before using the new instance. Do not delete previous volumes until the restored data has been verified.

## Before production use

This repository is a lab starting point. A production deployment needs HTTPS, an appropriate reverse proxy configuration, restricted network access, a persistent encryption key, and tested database and volume backups.

Consult the [official hosting documentation](https://docs.n8n.io/hosting/) for deployment requirements and the [n8n license](https://github.com/n8n-io/n8n/blob/master/LICENSE.md) for upstream usage terms.
